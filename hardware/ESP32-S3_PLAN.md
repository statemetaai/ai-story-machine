# ESP32-S3 故事机 · 硬件规划

> 目标：把网页版验证过的玩法搬到硬件上 —— 按按钮选故事、听娃说话、联网让 AI 编故事、喇叭读出来、屏幕显示故事名。
> 先做网页版验证 ✅ → 再做硬件版（现在这一步）
> 固件框架：Arduino / ESP-IDF（PlatformIO），先跑通，再接真 AI。

## 1. 总体架构

```
孩子说话 / 按按钮
      ↓
INMP441 麦克风 (I2S0 收) ──→ ESP32-S3 ──→ WiFi ──→ AI 故事生成 + TTS
      ↑                                                              ↓
      │                                              MAX98357A 功放 (I2S1 发) → 喇叭
      │                                                              ↓
      └──────────────── SPI-LCD 显示：主角 / 故事名 / 状态 ──────────┘
```

数据流一句话：**听（麦克风）→ 想（联网 AI）→ 说（喇叭）→ 看（屏幕）**。
ESP32-S3 本身不跑大模型，负责端侧采集、播放、显示和联网，故事生成和语音合成走云端 API，断网时用网页版同款本地模板故事兜底。

## 3. 引脚总表（按哥哥给的接法，逐项核对过）

### 3.1 麦克风 INMP441 / ICS-43434（I2S0，收）

| 麦克风 | ESP32-S3 | 说明 |
|---|---|---|
| WS | GPIO4 | 字选择 / 左右声道时钟 |
| SCK | GPIO5 | 位时钟 |
| SD | GPIO6 | 数据输出（麦克风 → ESP32） |
| VDD | 3V3 | **只能 3.3V** |
| GND | GND | 共地 |
| L/R | GND（短接） | 接 GND = 左声道，代码里就读左声道 |

- 采样率：16 kHz，16-bit，单声道（语音识别 / 故事指令够用）。
- 麦克风线 < 15 cm，远离喇叭和电源线，否则容易有电流声 / 啸叫。
- L/R 悬空会没声或时有时无，必须接 GND。

### 3.2 数字功放 MAX98357A（I2S1，发）

| 功放 | ESP32-S3 | 说明 |
|---|---|---|
| DIN | GPIO7 | 数字音频输入 |
| BCLK | GPIO15 | 位时钟 |
| LRC | GPIO16 | 左右声道时钟 |
| Vin | 3V3 | 电源输入 |
| GND | GND | 共地 |
| SD | Vin（短接） | 接高电平 = 常开，不关机 |
| GAIN | GND（短接） | 低增益档，音量保守，适合睡前 |
| Audio+ | 喇叭正极 | 一般是红线，不确定就问卖家 / 万用表测 |
| Audio- | 喇叭负极 |  |

⚠️ **三条红线，千万别碰：**
1. Audio+ / Audio- 是桥式输出，**绝不能把 Audio- 接到 GND**，也不能把 Audio+ 和 Audio- 短接。
2. 播放时不要让喇叭端子悬空 / 裸露，孩子能碰到的地方要装进壳里。
3. 3.3V 供电时 4Ω 喇叭约 1–1.5W，够卧室用；如果觉得小，下一版再改 5V 供电（功放支持 2.5–5.5V），不要直接把 3.3V 线换成 5V 而不检查其他模块。

- 采样率：16 kHz / 24 kHz，16-bit，和 TTS 输出对齐。
- 麦克风和功放用**两路独立 I2S**（I2S0 收、I2S1 发），时钟不共用，代码好写、不容易互相干扰。代价是多占 3 个 GPIO，ESP32-S3 管脚够用，值得。

### 3.3 显示屏 SPI-LCD 8Pin

| 屏幕 | ESP32-S3 | 说明 |
|---|---|---|
| GND | GND | 共地 |
| VCC | 3V3 | 电源正 3.3V |
| SCL | GPIO21 | SPI 时钟 |
| SDA | GPIO47 | SPI 数据（MOSI） |
| RES | GPIO45 | 复位 |
| DC | GPIO40 | 数据 / 命令选择 |
| CS | GPIO41 | 片选 |
| BLK | GPIO42 | 背光（PWM 调亮度） |

- 驱动：先按 ST7789 试，TFT_eSPI / LovyanGFX 都行；如果屏幕型号不是 ST7789，改驱动型号即可，引脚不用动。
- SPI 用 GPIO 矩阵自定义引脚，时钟建议先设 20–40 MHz，稳定了再往上加。
- BLK 直接接 GPIO42：先确认屏幕模块上已有背光限流电阻（大多数成品模块都有）。如果 BLK 脚是裸 LED，**必须串电阻或用三极管驱动**，不要直接大电流灌 GPIO。
- 屏幕只显示：主角、故事名、状态（正在听 / 正在想 / 正在讲）、音量。不要在屏幕上放长篇故事正文，孩子是听故事，不是看故事。

| GPIO | 用途 | 备注 |
|---|---|---|
| 4 | INMP441 WS | I2S0 |
| 5 | INMP441 SCK | I2S0 |
| 6 | INMP441 SD | I2S0 |
| 7 | MAX98357A DIN | I2S1 |
| 15 | MAX98357A BCLK | I2S1 |
| 16 | MAX98357A LRC | I2S1 |
| 21 | LCD SCL | SPI |
| 47 | LCD SDA | SPI |
| 45 | LCD RES | ⚠️ 见 §4，必须重点检查 |

未占用的安全 GPIO（留给按钮）：GPIO10、11、12、13、14、17、18、38、39 等。
不要用的：GPIO0（BOOT/下载）、GPIO3、GPIO46（启动配置脚），GPIO19/20（USB），GPIO26–32（部分板子接 PSRAM/Flash，视开发板而定）。

## 4. ⚠️ 必须先看的风险：GPIO45（LCD RES）

这是整份规划里**唯一一个高风险点**，先说清楚：

- GPIO45 是 ESP32-S3 的**启动配置脚（Strapping Pin）**，管 Flash 电压 VDD_SPI。
  - 启动时 GPIO45 = 低电平（默认内部下拉）→ Flash 用 3.3V，正常启动。
  - 启动时 GPIO45 = 高电平 → Flash 改用 1.8V，**3.3V Flash 的板子会无法启动**。
- 你的接法是 GPIO45 接 LCD 的 RES（复位脚）。RES 脚在很多 LCD 模块上有上拉，**上电瞬间如果把 GPIO45 拉高，就可能导致不开机**。
- 启动完成后，GPIO45 可以当普通 IO 用，问题只在**上电/复位那一瞬间**。

**怎么做才安全（二选一，推荐第 1 个）：**

1. **首选：把 RES 换到安全 GPIO**，比如 GPIO38 或 GPIO39，GPIO45 空着不用。
   改一行代码就行，屏幕其他脚不动。这是最稳妥的。
2. 如果坚持用 GPIO45：上电前用万用表测 LCD 的 RES 脚对地电阻 / 上电瞬间电压，确认启动瞬间 RES 是低电平或高阻态；并且在代码里**启动后先把 GPIO45 拉低 100ms 再拉高释放复位**。测不出来就不要赌，直接用方案 1。

> 一句话：**GPIO45 能用，但要先确认启动瞬间是低电平；不确认就换脚。** 其他 11 个脚都没有这个风险。

另外两个小提醒：
- GPIO47、GPIO40–42 在 ESP32-S3 上是普通 IO，没有启动配置作用，放心用。
- 不同开发板（DevKitC / Xiao / 其他）对 GPIO35–37、26–32 的占用不一样，买板子时确认一下是不是 N8R8（8MB Flash + 8MB PSRAM），故事音频缓存和 OTA 都需要 PSRAM。

## 5. 按钮规划（哥哥还没给，先按这个预留）

| 按钮 | 建议 GPIO | 功能 |
|---|---|---|
| 讲故事 / 说话 | GPIO0（板载 BOOT 键，先顶着用） | 按住说话，松开生成故事；短按 = 讲一个新故事 |
| 下一个 | GPIO10 | 换主角 / 换故事 |
| 音量 +/- | GPIO11 / GPIO12 | 长按调音量，屏幕显示音量条 |

- 按钮一端接 GPIO，一端接 GND，代码里用内部上拉，**不要外接 3.3V 到按钮上**。
- 先只做 1 个“讲故事”键就能跑通全流程，其他键是加分项，不要一开始全焊上。

## 6. 电源与功耗预算

| 模块 | 典型电流 | 备注 |
|---|---|---|
| ESP32-S3（WiFi 收发时） | 200–300 mA 峰值 |  |
| MAX98357A + 喇叭（中音量） | 200–500 mA 峰值 | 大音量会到 1A 左右 |
| SPI-LCD | 50–100 mA | 背光最耗电 |
| INMP441 | < 5 mA | 可忽略 |
| **合计** | **建议按 5V/2A 留余量** |  |

- 第一版：USB-C 5V/2A 电源适配器供电，不要长期用电脑 USB 口。
- 所有模块共地（GND 连在一起），电源线粗一点，麦克风和功放不要共用一根细杜邦线供电。
- 电池版是下一阶段：18650 + 升压/充电板 + 电量显示，先不做，先把插电版跑通。

## 7. 固件架构（先搭骨架，再接真 AI）

```
setup()
  ├─ 串口打印启动信息
  ├─ LCD 初始化：显示 “故事机启动中…”
  ├─ I2S0 麦克风初始化（16kHz）
  ├─ I2S1 功放初始化（16kHz）
  ├─ WiFi 连接（配网：先写死家里 WiFi，后面再做配网页）
  └─ 显示主界面：主角 + “按按钮讲故事”

loop()
  ├─ 按钮：短按 → 讲一个本地模板故事（网页版同款）
  │         长按/按住说话 → 录音 → 发给 AI → 拿回故事音频 → 播放
  ├─ 播放时：LCD 显示故事名 + 进度，按钮可暂停
  └─ 空闲时：LCD 熄屏 / 低亮度，省电
```

分阶段做，每阶段都能独立验证：

| 阶段 | 做什么 | 通过标准 |
|---|---|---|
| H1 | 点亮 LCD，显示主角和一句话 | 屏幕亮，字不乱 |
| H2 | 功放出声：播一段提示音 / 本地 WAV | 喇叭响，音量可调，无电流声 |
| H3 | 麦克风录音：录 3 秒，回放出来 | 能听到自己的声音 |
| H4 | 本地故事：按钮 → 讲网页版模板故事 | 不联网也能讲完整故事 |
| H5 | 联网 AI：录音 → AI 生成 → TTS → 播放 | 娃说一句话，AI 接着编 |
| H6 | 收尾：OTA、音量记忆、收藏、低电量提示 | 断电重启后设置还在 |

> H1–H4 不需要 AI Key，先做；H5 再接 AI，到时哥哥选 AI 服务，我来接。
